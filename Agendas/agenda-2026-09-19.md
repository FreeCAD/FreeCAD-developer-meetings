3. **Proposal to limit PR size** (kadet1090)
   - We have more and more 2k+ lines PRs 
   - Big PRs take exponentially more time to review: 
     - they usually contain few different things that are part of the same feature, but touch different areas
     - it's not possible to review them in one sitting 
     - due to multiple areas being touched it's hard to give proper time and focus to every one of them
   - The proposal is to request from PR authors splitting the PRs into **well-scoped** chunks of no more than 500-700 lines of code
   - The big PR can still be opened to serve as context for the reviewer if the full picture is needed
   - The big PRs shouldn't be fully prohibited - but authors need to take into account that they will be way longer in the queue
   - This should only really affect functional changes - mechanical PRs like formatting, refactor that updates all call-sites etc should still be done as one big PR
   - Link Array PR was split like that and it both resulted in faster reviews, better reviews and shorter time in the queue per PR
