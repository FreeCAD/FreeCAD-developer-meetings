4. **Should sketcher group constraint be marked as experimental?** (pierreporte)
   - It is quite different to group constraints in other CAD programs
   - It’s closer to a block, but it doesn’t have its most useful feature
   - It’s dangerous to keep such feature with such name because we need to support it forever
   - It is used by the text tool, which is fine and can be improved
   - I propose to mark the group constraint as experimental in 26.3
   - With this status, we can break it later to make it good
   - The code would stay behind the scene for the text tool (would need a refactor)
   - Meeting attendees agreed that the current "block" constraint should be marked experimental and hidden from users
   - @kadet1090 also proposed that the text tool itself be marked experimental, and the consensus was that was a good idea
   - @pierreporte will make a GitHub Issue to advance this process

6. **Toolchain Standards** (oursland)
   - Recently I reviewed a PR that employed constructs that depended upon C++23 and Python 3.12.  Both of these are "supported" by Ubuntu 24.04.  [GCC 13 is packaged](https://ubuntu.com/developers/docs/reference/availability/gcc/) in Ubuntu 24.04 and supports C++13, despite being released in 2023 but ISO ratification in 2024.
   - C++23?
   - Python 3.12?
   - Consensus in the meeting was that we should move to support C++23 officially, but explicitly continue to require that code compile on Ubuntu 24.04 (so not *all* C++23 features are available)
   - Python 3.12 is known to work fine with FreeCAD
