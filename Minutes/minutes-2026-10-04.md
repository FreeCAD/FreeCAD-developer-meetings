1. **Bounty Issue Identification**
   - With the 26.3 branch created, bounties should focus on completing release blockers.
   
2. **FreeCAD 26.3 release** (Max)
   - 26.3 was branched, more info and schedule: https://github.com/FreeCAD/FreeCAD/discussions/32821
   - All PRs target main. Please add the 26.3 milestone to your PRs which need to be in 26.3 or tag me so I can assign it. Focus is on fixes.
   - Please assign the `backport releases/FreeCAD-26-3` label to the same PRs and tag me for automatic backports of merged PRs.
   - Add blocking issues if something critical is broken and tag me.
   - Translators get strings now from the release branch. Limit UI changes and no UI/string changes after the first RC (approx. 2 weeks after branching).
   - Update [release notes](https://wiki.freecad.org/Release_notes_26.3) and document your own changes!
   - For reviewing, use the Release Priority view: https://github.com/orgs/FreeCAD/projects/40/views/11 (Manually ranked: Blockers, PRs that fix blockers, PRs that fix regressions, PRs that are approved, other bugfixes.

3. **Consistent line endings** (Flaviu)
   - FreeCAD has a lot of different line endings in source files, sometimes *multiple* different types of line ending in one file.
   - Any amount of human effort spent thinking about line endings is a waste of time, [so let's consolidate to just one](https://github.com/FreeCAD/FreeCAD/pull/32006)
   - Main concern from maintainers is the automatic backport action: if we make a bulk change, will all subsequent PRs fail the automatic backport?
   - Possible alternative to monolithic change PR would be to go directory by directory, but it's not clear if that provides any real benefit, and it complicates the .git-blame-ignore-revs file
